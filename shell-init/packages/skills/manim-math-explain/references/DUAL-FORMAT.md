# 双画幅：横屏 × 竖屏（Phase 3–4 必读）

同一套数学叙事，服务两个平台：

| | 横屏 landscape | 竖屏 portrait |
|---|---|---|
| 比例 | 16:9 | 9:16 |
| 典型 | 1920×1080 | 1080×1920 |
| 平台 | B 站、YouTube | 抖音、视频号、Reels |
| 信息密度 | 可稍高 | 必须低；英雄更大 |
| 口播 | 完整 `script.md` | 完整或 `script_short.md`（策略 B） |

---

## 两种产品策略（Checkpoint 3 选定）

### 策略 A · 双渲染自适应（默认推荐）

- 同一 `Scene` 类，运行时读 `MANIM_FORMAT=landscape|portrait`  
- 逻辑动画共用；**仅布局函数分支**  
- 竖屏：纵向堆叠、公式拆行、对比改为上下  

适合：机制演示类（旋钮、箭头、数轴）本身竖屏友好。

### 策略 B · 横屏完整 + 竖屏切片

- 横屏按长稿做满  
- 另写 `outline_short.md`：钩子 + 1 个核心推导 + 金句（30–90s）  
- 竖屏可单独 `scenes_short/`  

适合：长推导、多公式、需要板书宽度的集。

---

## 布局原则

### 横屏 16:9

- 英雄可居中或左内容右注释  
- 数轴、左右对比自然  
- 公式可单行，但仍避免墙  

### 竖屏 9:16

| 规则 | 说明 |
|---|---|
| 上半安全区 | 标题/问题放中上部；避开平台 UI 遮挡（顶底各留 ~12%） |
| 禁止左右双栏 | 对比改上下或时间先后 |
| 公式宽度 | `MathTex` 超宽则按 `=` 或运算符拆行 |
| 字号 | 英雄字 ≥ 横屏视觉占比；正文宁少勿小 |
| 一次更少 | 同屏元素再砍 30% |

### 安全区示意（竖屏）

```
┌─────────────┐
│  平台 UI    │  ← 勿放关键信息
│·············│
│   问题/英雄  │
│   主动画    │
│   辅助标签  │
│·············│
│  平台 UI    │
└─────────────┘
```

## 实现约定（脚手架）

`scenes/shared/layout.py` 提供：

- `get_format()` → `"landscape" | "portrait"`  
- `place_hero(m, fmt)`  
- `stack_vertical(*mobs)`  
- `formula_block(tex, fmt)` → 自动拆行策略  

`manim.cfg` 或 CLI：

```bash
# 横屏
manim -pqh scenes/01_hook.py Hook

# 竖屏
MANIM_FORMAT=portrait manim -pqh scenes/01_hook.py Hook -r 1080,1920
```

像素以项目 `RENDER.md` 为准；逻辑上**不要**写死 1920 坐标，多用 `UP/DOWN` 与比例。

## 平台导出提示

- B 站：横屏主成片；封面另制  
- 抖音：竖屏；标题/封面字承接「本集一问」；系列用统一片头 1s  
- 若只做一版：在 Checkpoint 0 声明，仍建议布局函数预留分支，避免日后返工
